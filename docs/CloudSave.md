# 账号云存档

正式入口 `scripts/main.lua` 启动账号同步。完整存档包含收藏、开局草案、当前家谱、人物、家史、账本、待决事件和随机数状态。

## 保存与续玩

- 游戏启动后，先等待 TapTap 身份就绪，再读取账号云存档。读取完成前暂停进入游戏和写入进度。
- 新局和每次已确认的游戏安排都会自动保存；完整开局草案的修改每两秒检查一次。
- 本机使用两个交替文件保存，写入后回读核对。账号 ID 与云变量名称共同构成本机文件名称。
- 云端使用 `clientCloud:Get`、`clientCloud:Set`。上传前读取当前版本，上传成功后再次读取并核对内容。
- 换设备登录同一 TapTap 账号后，完整恢复云端家谱。旧设备再次打开时，自动接续同一条历史上的新进度。
- 上传期间新增的安排继续保存到本机；前一次上传确认后自动续传最新进度。
- 游戏回到前台或失去焦点时立即发起同步。页面中的同步状态用于确认云端是否已经收到进度。

## 网络与冲突

请求超时或网络中断后按 2、4、8、16、30 秒间隔重试。待上传版本号、所基于的云端版本号和当前进度一并写入本机文件，重启后可以继续核对并上传。

云端和本机各自发生变化时，暂停游戏并显示两份家谱摘要，玩家可以选择使用云端进度或本机进度。选择本机后，仍会重新读取云端版本，确认期间出现的新变化继续进入冲突选择。每份云存档保留最近 64 个祖先版本号；无法证明属于同一条历史时也进入选择流程。

TapTap 云变量接口提供普通读取和写入。服务端未提供条件写入接口，同一瞬间的多设备写入无法实现原子互斥；客户端通过版本历史、上传后的回读以及各自保留的本机进度识别分叉。

原生设备可以保留尚未上传的本机进度。WASM 预览的文件系统位于内存，刷新会丢失尚未同步的数据；应等待页面显示“家谱已自动保存到云端”后再刷新或切换设备。

## 数据位置

- 云变量：`jiaye_save_v1`，由 Maker 按当前项目和 TapTap 玩家隔离。
- 本机文件：`jiaye_jiaye_save_v1_<账号ID>.json` 和对应的 `.backup.json`。
- 云端数据版本：`format = 1`；游戏存档版本沿用 `State.SAVE_SCHEMA_VERSION`。
- 旧版本机家谱在首次账号同步时迁入；存在另一份云端家谱时显示选择页面。

## 验收

`scripts/QA/CloudSave.lua` 使用真实 `clientCloud` 接口和独立验收云变量，依次检查自动上传、空白本机恢复、旧设备续玩、两种冲突选择以及上传期间的新安排。不同设备使用独立本机文件名称，正式云变量和正式家谱保持独立。

正式入口为 `main.lua`。验收入口使用完毕后需将 Maker 预览入口恢复为正式入口。
