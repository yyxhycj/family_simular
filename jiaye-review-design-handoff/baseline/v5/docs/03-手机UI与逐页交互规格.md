# 03 · 手机 UI 与逐页交互规格

## 1. 设计基准

以 V5 为已接受视觉，不重新提出另一套风格。墨绿为书封与主操作，米白为阅读内页，草绿表达选中/进展，赭红表达成本警告和风险。纯文字不等于所有字号一样，也不等于后台表格。界面应像可操作的家谱，但所有按钮要让第一次接触的人看得懂。

设计 token 来自 `source/prototype/mobile.css`：背景 `#f5f3ed`，卡片 `#fffefa`，正文 `#263c33`，次要文字 `#616b63`，弱化文字 `#7b8176`，分割线 `#dddeda`，强调色 `#37634d`，危险色 `#a44e38`。保留系统中文字体回退，不依赖外部字体请求；包中不分发字体文件。

目标正文15–16px、故事行高约1.85–1.95、输入16px、主要按钮约46–49px。最终由真机检查决定，不以小字号挤入更多字段。触控热区至少44px是本项目设计目标，不代表本包已通过任何外部认证。文本放大、不依赖颜色提示、焦点可见和减少动画为必要体验要求。

## 2. 导航和页面结构

创建流程：**世道 → 族人 → 家底 → 信物 → 落笔**。五步能回访；返回不丢草案。头部有家谱和更多菜单，底部固定预算与下一步，下一步≠立即花资源。

游戏导航：**家族 / 族人 / 家业 / 藏阁 / 家史**。家史包含历代族长、年鉴、终章子入口。推进年份是独立主操作，不伪装成第六个底部 tab。藏阁区分本局实际物件和跨局解锁收藏，标题必须标清范围。

### 层级规则

最底部导航固定；年度推进条在其上方。安全区、底部浏览器工具栏和软键盘占位均计入可用高度。内容应留出足够底部空间，最后一个选择和保存按钮不能被遮挡。长人物详情是整屏面板；短菜单、预算/家谱查看用底部面板。弹层打开时锁定背景滚动，关闭回到原焦点和原滚动位置。

“概况 / 安排 / 经历”在 V5 是同一人物详情的章节定位，并不是切换到三个互相丢状态的表单。正式版保留这个使用结果，内部可使用明确路由或组件，不再按文案正则查找按钮。

## 3. 页面 P01：世道与来处

上方五步、页级随机/撤销、世界标题和已选家谱入口。姓氏可编辑；时期用单列整卡，年份使用当前时期的选择控件；推导时世显示为只读结果。来历与地区显示名称、总价、实际效果和选中标记。

点击时期时联动年份/时世/预算/家谱，其他字段不动。长效果可展开，不把关键代价藏在详情。当前页分值放底栏，全球100点放预算详情。超分只出现清楚提示，不阻止玩家返回前页编辑。

## 4. 页面 P02：家中这些人

不使用必须横滑的表格。列表卡显示姓名、年龄、代际、主业、资质、本领摘要、当前花费、族长标记和“查看与编辑”。可添加、移除、指定首任族长。删人前说明被引用的关系和族长选择会受影响，确认后重新校验，不把无效引用带进开局。

个人编辑分基础资料、亲属、潜力与经验、初始安排。年龄输入使用数值键盘；关系选择显示名字与年龄，不能只有内部ID。保存按钮固定，错误在相关字段和顶部汇总同时可见。尚未保存时预览临时变化，取消回退。任何潜力/人数变化都实时计价。

## 5. 页面 P03：安身家底

现银、存粮、田地使用标签明确的步进器；给出单位、当前数量、单价与本项点数。最小值0不能减为负；输入非法数字需就地提示。住宅单选，产业独立开关；家风与关系逐项选择。每次变更同步家谱和估计收支。

把“初始拥有资产”与“后续每年收益”分开写。作坊无人经营时明示不会得到经营收益。不能因为总分超出就拒绝输入，草案仍可调；开始时统一限制。

## 6. 页面 P04：随身旧物

已解锁项展示名称、点数、故事入口、作用、是否带入；未解锁项显示锁定状态和线索。可以查看锁定详情，不可勾选。已选不代表无条件拥有升级版本；多选遵守总分，当前不引入额外槽位。

随机只在已解锁池产生组合。查看藏阁再返回恢复同一页草案；新解锁提示不能覆盖玩家当前填写的数据。基础物件与进阶物件保持可读区分，不以“稀有金色”暗示一律更优。

## 7. 页面 P05：落笔之前

展示完整家谱摘要和各页费用。错误包含具体项目和跳转入口。显示总计与上限，不重复列一个会被收费的“确认页”。开始按钮禁用的同时旁边解释原因；清空错误后恢复。正在确认覆盖旧局时，保留取消入口、说明收藏保留范围；最终提交再次校验。

整局随机与普通开始分离，需确认；撤销可见。未花完的点数不阻止开始，也不会自动兑换成家财。

## 8. 页面 G01：家族近况

先展示当前年份/时代/家族印记和简短近况，再显示人口、钱粮、声望及必要趋势。正文重点是待决事件或上一年结果，不是六张同等优先级的大卡片。族长、近期记事、需要注意的成员均可直接跳转。

资源显示需区分“当前余额”“今年预计变化”“已经结算变化”。推进有待处理事件时，把用户定位到事件，说明原因，不悄悄忽略。推进按钮显示忙碌状态，连点只提交一次。

## 9. 页面 G02：事件决定

正文→来源/涉及人物→选择执行人（适用时）→选项→结果预告→确认。选项整卡可点，选中有勾选与边框，不能只有颜色。花费不足时保留可读说明并禁用；未选择时不能确认。提交后显示实际结果和家史入口。

预计一年后发生的事情不能当作当场已得奖励。调查者离世、物件出售、其他前提改变时显示新的处理方式；不让失效事件永远堵住推进。决定提交采用事件实例ID，旧弹窗不能重复扣款。

## 10. 页面 G03：全体族人和详情

列表能按在世/成年/孩子/已故以及姓名筛选；空结果给清空筛选入口。所有族人都可访问，不因分页/虚拟化失去某个角色。长局只优化渲染，不改变玩家操作范围。

详情顶部姓名、角色、年龄、当前主业；概况展示能力与关系；安排展示当前选择、合法性、下一年成本；经历倒序记录。保存操作与返回分离。已故或已终局成员详情只读；婚事、生育计划、应试等按钮只在满足条件时出现或解释禁用原因。

## 11. 页面 G04：家业

显示公库、粮储和本年估算，附展开账目。资产卡列出数量/经营者/效果/维护费，可置办或迁居。重大支出二次确认，确认时重新检查金额与对象，不重复扣款。

个人财产、分支账目未实现时不显示假余额。后续引入时以“公库 / 各户 / 产业”清楚区分范围，不把所有钱默默合并。

## 12. 页面 G05：藏阁

两个范围：本局物件（实际存在、保管人、调查进度、出售状态）和已解锁目录（下局可选资格）。物件详情展示来源、历史、当前状态、托付/继续调查/出售。出售的损失明确写出；已解锁资格不因出售消失。

调查有多个阶段时显示当前步骤和可操作项，不展示保证未来成功的假进度。取得新解锁使用轻提示并入历史；不强制跳出当前事件。

## 13. 页面 G06：家史、继任与终章

家史子导航必须可见。年鉴按年/人物/事件来源查看；历代族长显示不同的任职区间而非只显示任数；点击可以读完整人生。继任面板能比较候选当前工作和已有经历，确认后不把候选从主业中移走。

终章分可探索、已有资格、已达成；设计条目明确标识且不能结束游戏。确认发展终章前说明本局只读；最终页显示主结局、真实年数、世代、关键人物与历史依据，可翻阅旧史或创建新局。

## 14. 通用状态与移动要求

| 状态 | 必须表现 | 禁止 |
|---|---|---|
| 保存中/提交中 | 操作锁定、简短状态，成功后释放 | 连点产生两个年度或两次婚事 |
| 数据错误 | 人类可读原因、修复入口 | 只有控制台报错或无声默认值 |
| 本地存储失败 | 明示临时状态，提供导出 | 假显示“已保存” |
| 锁定内容 | 条件提示、可以读详情 | 可点后才告诉用户未开发 |
| 页面返回 | 原草案、选中、滚动位置恢复 | 重新生成一家人 |
| 键盘弹出 | 当前字段和保存仍可用 | 键盘覆盖固定底栏 |
| 文本放大/长姓名 | 合理换行、按钮仍可触达 | 字体缩小、截断代价或隐藏族人 |

视觉验收覆盖320（边界）、360、390、430、768和桌面宽度；当前主目标360–430竖屏。真机覆盖至少一个iOS浏览器和一个Android浏览器，记录具体机型、系统、浏览器与输入法。截图只能证明截图所见，滚动、焦点、软键盘和安全区需交互记录。

## 15. 页面交付物

每页必须提供：正常/空态/错误/禁用/已结束状态；布局及滚动说明；按钮映射到命令；字段来源；返回行为；一个可复现用例。对应实施手册的UI步骤与QA用例。不要只给漂亮首页，把人物编辑、超分和结局放回旧样式。
