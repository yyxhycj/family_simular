# 06 · 逐步实施手册

> 本手册用于在正式工程中实施，不表示这些开发步骤已经完成。V5提供参考行为，本交付已完成原型整理与局部冒烟。每步先完成当前目标、验证，再继续；不允许一次提示让工具重写全项目。

## 一、先后顺序与可试玩节点

**A（S00–S01）保基线 → B（S02–S05）规则与存档 → C（S06–S10）创建闭环 → D（S11–S18）完整凡世纵向切片 → E（S19–S20）内容与家庭深度 → F（S21–S25）正式体验与发布 → G（S26）下一个世界。**

S06可与部分规则工作并行，但没有S04/05不能把临时表单当运行存档。S18结束时必须能玩一轮：自由配点→安排人物→一年推进→信物调查→继任→取得/确认终章→解锁→再次开局。S19–S20扩展时仍保留这个可玩的版本。S21在核心页面开发时持续做，最终验收依赖真实功能。

不承诺固定工期；先按现有工程和人手估算每步。多人协作可按规则/客户端/内容/测试分工；单人开发按依赖顺序执行。新增框架、服务器、安装包不是默认前置。

## 三、每一步具体怎么做

### S00 · 冻结版本与建立玩法基线

**阶段：**A·保住已确认的版本。 **前置：**无。

**先读 / 复用：**prototype/jiaye-demo-v5.html；本包00、09文档；qa/current-smoke.json。

**执行：**

1. 复制原型作为只读基准，记录源文件哈希；正式工程新建工作分支或独立工作目录，不直接覆盖唯一文件。
2. 逐项核对R01–R17；把旧建议中的每页配额、手动年份、自动回退资质、固定带入一件等与现版本冲突的规则移到废弃记录。
3. 实际走一遍默认97点开局、超分无法开始、随机撤销、人物安排、老木尺后续、族长交接与发展终章确认。
4. 建立功能状态矩阵：有原型、有简化实现、缺失、待讨论。明确13个判定、144条草案与100+目标的区别。

**本步交付物：**冻结版本清单与哈希；基线存档、截图与操作脚本；需求追踪表。

**完成标准：**

- [ ] 没有删改V5玩法或UI
- [ ] 所有功能状态有源代码/界面依据
- [ ] 已有进度保留且能导出

**未通过时：**基准文件无法运行或同一规则出现冲突时，先登记与复现，不一边修复一边重设计。

### S01 · 建立可重建工程入口

**阶段：**A·保住已确认的版本。 **前置：**S00。

**先读 / 复用：**source/prototype/和tools/build_prototype.py已提供可逆拆分。

**执行：**

1. 运行随包重建脚本，确认输出与冻结V5按字节一致；记录Node语法检查结果。
2. 把CSS、内容常量、模拟函数与UI适配分到目标目录，保持导出HTML或网页入口可运行。
3. 每次只迁移一类职责，查清V3/V4后置函数覆写顺序，不能只保留同名函数的第一个版本。
4. 接入现有工程的本地测试命令与运行说明；未选框架时先保留无依赖JavaScript，不先造服务器。

**本步交付物：**一个明确的启动/构建入口；可回到旧实现的提交节点；函数迁移映射表。

**完成标准：**

- [ ] 开发环境与预览读取同一内容源
- [ ] 移动页和原型行为无差异
- [ ] 没有漏掉V4预算/日期/随机覆盖函数

**未通过时：**出现不明差异时回退该批迁移，用旧输入重放定位。

**完成标准：**

- [ ] 只有一份价格来源

### S03 · 明确状态、人物ID和亲属关系

**阶段：**B·建立稳定规则。 **前置：**S02。

**先读 / 复用：**rawPerson、makeGame、generation、ancestors、kinConflict。

**执行：**

1. 定义Profile、Draft、RunState以及成员、亲属边、任职、信物实例、事件实例的类型/校验。
2. 用稳定ID关联人物；重名不合并，死亡不删除，新增人不复用旧ID。
3. 实现关系全量验证：引用存在、祖先无环、成年配偶双向、一致的年龄规则；养亲和监护单独表达。
4. 把世界日历、本局yearIndex、成员年龄分开；开局记录是初始事实，不增加实际职业人年。

**本步交付物：**状态定义与关系校验函数；合法/非法家庭夹具；默认97点家庭转换样本。

**完成标准：**

- [ ] 重名人物仍可分别操作
- [ ] 祖孙/配偶关系无悬空引用
- [ ] 更改日期不伪造经营时长

**未通过时：**未知关系不能猜测自动补写；返回字段级问题。

## 四、一次开发任务的交接格式

每次提交必须回报：步骤ID；实际修改文件；复用的旧行为；新增/修正的规则；已执行测试与证据；未执行测试；存档影响；遗留问题；下一个允许开始的步骤。不要只说“已完成优化”。

通过后在 `tasks/steps.json` 的副本更新状态、负责人和提交号。本包内状态表示计划，不自动因为有Demo就改成完成。
