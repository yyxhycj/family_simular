# 08 · AI开发总提示词与分步用法

## 1. 怎么交给开发工具

先将整个交付目录放入现有项目的文档目录，或新建工作目录再解压。首次任务只做S00–S01：核对、基线、构建入口。后面一次只执行一个步骤或明确的一小批子任务。不要直接下达“把全部27步一口气做完”，否则难以控制规则、UI和存档回归。

本包不预设某个IDE或代理，也不要求安装新的外部服务。若已有正式工程，先读它的目录和运行方式；没有正式工程时从随包可重建HTML开始，不重新设计一个不相干的脚手架。

## 2. 可直接复制的总提示词

```text
你正在继续开发《家业》，一个纯文字、多代、全员可安排的家族人生模拟器。

工作范围：当前只做凡世王朝。以本交付包的V5手机UI和已确认规则为基线，不重做视觉，不改变玩法方向。先读README、docs/00、docs/06与docs/09，再按当前任务阅读专项文档和实际源码。未读源码前，不宣称功能存在或缺失。

必须保留：
1. 每位成员都可以安排。族长是职位，可主动替换；换任/死亡不重置家族、其他人的工作和历史。
2. 家族才是一局主体。没有固定年数或代数上限。发展终章取得资格后确认结束；族长无亲生子不等于灭族。
3. 一个100点总预算，各选项独立定价，自由组合。没有分类配额，没有自动均衡，没有自动删人降级。
4. 按页显示本页已用/(100-其他页已用)，不是每页另有100点。允许超分草案，按钮/处理器/最终确认均拒绝超分开局。
5. 开局时期与可选年份推导同一时世，不允许手填年份加独立时世。世界日期、本局经历、成员年龄分开。
6. 每页随机只改该页，尊重共享额度与已解锁内容，可撤销；无解保留草案。确认页整局随机另行确认。
7. 家谱实时显示具体选择。编辑未保存只在副本预览；取消完整恢复。
8. 信物解锁资格和本局实体分开，初始三件可选；以后解锁增加选项，不提高100点上限。V5带入可多选，不新增固定槽位。
9. 13个原型判定≠144条已实装。旧目录只当设计素材；完整游戏100+结局需真实不同路径并经过验证。
10. 手机优先，保留墨绿/米白的V5样式、五步创建和家族/族人/家业/藏阁/家史五主导航；不能通过删功能改善截图。

执行纪律：
- 只执行当前指定的步骤，先列改动范围和依据，再实现。
- 复用现有函数/规则，不复制多份价格或平行状态。发现后置覆盖函数，要确认当前有效版本。
- 原型源码的存在不等于正式功能验收完成。新计划、新实现、已验证分别说明。
- 小步改动，先纯函数/状态边界再替换UI；保留可回退版本和旧存档。
- 不擅自加新世界、服务器、付费、云同步、战斗地图、AI裁定或新的开局限制。
- 不把文案生成当模拟引擎；人物/财产/亲缘/生死由规则事实决定。
- 不隐瞒没运行的测试。模拟浏览器、内存存储替身、真实持久化和真机必须分开记录。

完成本步必须返回：
1. 步骤ID与实际改动文件。
2. 每条已实现/保留的行为及其证据。
3. 执行的测试、输入、实际结果；未执行项和原因。
4. UI截图（涉及UI时）、存档影响和回滚方法。
5. 剩余问题，以及下一个可以开始的步骤。

当前先执行 S00：冻结版本与建立玩法基线。完成后停止，不自动扩展到后续系统。
```

## 3. 后续单步指令模板

```text
继续《家业》，本次只执行【Sxx · 步骤标题】。
读取 docs/06 中对应步骤及其前置产物；同时读取专项文档、原型相关函数和qa用例。

先确认：前置是否完成、当前原型已有多少、这一步具体新增/替换什么。
然后按步骤的操作顺序实现。禁止顺手改总分、选项价格、世界规则或V5视觉。
每个子任务完成后运行对应测试；不能执行的项目如实标为未执行。
最后按总提示词的五项交付格式总结，并停止等待下一步。
```

## 4. 四个可直接使用的专项任务

**创建流程回归：**只处理S07–S10范围。先证明默认97点四页预算和超分双闸门正确，再处理卡片、实时预览、随机/撤销。不能为适应手机把选项移除。交付合法/非法草案样本及手机点击录屏。

**信物纵向切片：**只处理S17中的老木尺。必须实际从开局带入到调查、延迟、修复、解锁、再开局可选，另测暂缓、慢查、出售、人物离世、重复提交。不要一次扩充几十个只有名字的物件。

**新增一个终章：**先证明其依赖系统已实装；填写templates/ending.example.json对应规格，再做条件、样本、回顾文案、手机卡片与只读。若仅与旧结局阈值不同，合并为评价档位，不作为新结局计数。

**手机UI整合：**只处理S21页面状态，继承V5 tokens与导航，不改模拟函数。显式绑定命令而非按可见中文寻找按钮；检查键盘、安全区、空态、锁定、超分、终局。截图说明尺寸，不声称模拟器就是真机。

## 5. 遇到冲突时的处理

用户最后确认规则高于早期方案；新目标规格不自动覆盖已开始家族的历史。若涉及玩法变更，给出“当前行为/用户决定/建议修正/影响”再请求明确决定；纯实现细节可按本文档默认建议推进并记录。不要把未知说成已决定，也不要对每一个命名问题都中断开发。
