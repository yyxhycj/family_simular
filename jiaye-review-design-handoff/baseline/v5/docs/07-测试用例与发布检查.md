# 07 · 测试用例与发布验收

## 1. 测试证据边界

`qa/current-smoke.json` 为本次对冻结V5执行的38项选择性冒烟，包含100个页级随机候选样本及所列宽度的开局布局检查。运行方式为桌面Chromium、`set_content`、显式内存localStorage替身；不覆盖文件协议持久化、真机、完整长局平衡或所有终章正常达成。原型未被本轮改变。

下面88条是正式开发的验收设计，**默认未执行**。不能因与冒烟名称相近而自动标通过。对应机器可读清单在 `qa/acceptance-cases.json`。

## 2. 必须阻断发布的问题

数据丢失/导入覆盖错误；超分可开始；连点重复结算/扣费；终局后仍能写状态；出售后领奖；族长死亡误灭族；人物或设置被擅自删除；关键手机操作不可达。非阻断内容问题也需记录，并对外准确标范围。

## 3. 执行记录格式

每条记录：用例ID、构建哈希、规则/内容版本、平台/浏览器/屏宽、输入存档/种子、操作、预期、实际、证据文件、结论（通过/失败/未执行/阻塞）、缺陷关联。纯规则测试、模拟浏览器、真机、真实试玩分别标层级。截图只验证图中状态，不能证明整个流程。

## 4. 详细用例

### 共享预算与开始

**TC-BUD-01**　前提：默认家庭97点。
操作：分别打开四个分配页。 预期：20/23、47/50、24/27、6/9；同一余量3点。

**TC-BUD-02**　前提：总分99、100、101的三个合法草案。
操作：从按钮和确认处理器各开始一次。 预期：99与100允许；101拒绝且不改旧家族。

**TC-BUD-03**　前提：某一页集中使用大部分预算。
操作：合法地完成其他页。 预期：允许集中投入，不要求分类最低配额。

**TC-BUD-04**　前提：其他页成本已经101。
操作：打开一个0分页面并随机。 预期：解释容量不足，其他页不变，不能开始。

**TC-BUD-05**　前提：数字NaN/Infinity/非法负资源。
操作：计算预算和开始。 预期：拒绝非法草案，不按零费用蒙混。

**TC-BUD-06**　前提：确认覆盖框已打开。
操作：草案在确认前变成超分。 预期：最终处理器重新校验，原局原样保留。

**TC-BUD-07**　前提：人数从2变成8。
操作：提升每人资质并查明细。 预期：每人资质逐项计分，不存在全族固定低价。

**TC-BUD-08**　前提：价格数据采用小数。
操作：反复加减再到100边界。 预期：同一最小单位运算；显示与闸门一致。

### 时间与来历

**TC-TIME-01**　前提：安定盛年72年。
操作：切换变局将至再选156。 预期：时世风雨欲来；时期只收费一次。

**TC-TIME-02**　前提：变局时期。
操作：尝试注入72年或独立peace时世。 预期：校验拒绝，不发生日期/时世冲突。

**TC-TIME-03**　前提：世界历156年且开局三代。
操作：开始游戏。 预期：本局实际经历0；职业/传承没有虚构记录。

**TC-TIME-04**　前提：运行中通过事件改变时代。
操作：推进到与开局映射不同的日历。 预期：保留事件演变，不自动回到开局时世。

**TC-TIME-05**　前提：寒门高家财或名门低家财。
操作：完成创建。 预期：合法组合允许，不赠送/扣减额外隐藏资产。

**TC-TIME-06**　前提：原有不同地区主业。
操作：只改开局地区。 预期：仅地点/价/预览改变，原有成员与本领不重置。

### 随机与撤销

**TC-RND-01**　前提：第一页有其他页人工配置。
操作：随机本页。 预期：只时期年份来历地点改变；姓氏和其他页相同。

**TC-RND-02**　前提：第二页额度很少。
操作：随机族人。 预期：合法成员/成年首任族长；无解解释且保留草案。

**TC-RND-03**　前提：第三页已有资产设置。
操作：随机家底再撤销。 预期：只本页快照恢复，其他页不变。

**TC-RND-04**　前提：仅三件基础信物已解锁。
操作：反复随机信物页。 预期：不出现四件未解锁物，允许空集合。

**TC-RND-05**　前提：本页随机后又手动修改同页。
操作：尝试撤销随机。 预期：旧撤销不可用，不覆盖手动编辑。

**TC-RND-06**　前提：本页随机后别页花费增加。
操作：撤销本页。 预期：只恢复本页；若超分显示并拦开局。

**TC-RND-07**　前提：确认页选择随机整局。
操作：先取消再确认。 预期：取消无变；确认结果合法且可整局撤销。

**TC-RND-08**　前提：保存种子和随机状态。
操作：重放同输入/版本的随机过程。 预期：正式实现候选可复现，渲染不耗模拟随机。

### 实时预览与表单

**TC-PRE-01**　前提：打开家谱。
操作：变更时期、地区、家风、信物。 预期：每项具体值及名称更新，有文字变更标记。

**TC-PRE-02**　前提：编辑人物尚未保存。
操作：修改姓名年龄能力。 预期：临时预览更新，但现有RunState不变。

**TC-PRE-03**　前提：人物临时编辑已产生费用变化。
操作：取消/返回。 预期：人物、费用和关系恢复；没有半保存。

**TC-PRE-04**　前提：已开始一局，另开创建草案。
操作：随机或修改成员。 预期：当前运行家族和收藏不受影响。

**TC-PRE-05**　前提：长姓氏与同名成员。
操作：保存并打开预览。 预期：安全转义不执行HTML；重名不合并。

**TC-PRE-06**　前提：手机家谱面板滚动到底。
操作：连续改变相关字段/返回。 预期：内容同步，返回与滚动位置合理，后台无误操作。

### 成员与职业

**TC-MEM-01**　前提：已有多位族人与不同主业。
操作：逐人查看保存安排。 预期：人人可操作，其他人安排不被覆盖。

**TC-MEM-02**　前提：孩子或低技能成人。
操作：选择不满足条件的岗位。 预期：显示年龄/技能原因，不可绕过校验。

**TC-MEM-03**　前提：学习中的成员达到出师条件。
操作：推进到触发年度。 预期：询问去向，不自动转行收费。

**TC-MEM-04**　前提：成年人通过应试。
操作：返回人物页。 预期：资格保留，任职由玩家安排，原主业未改。

**TC-MEM-05**　前提：同一人本年已应试。
操作：再次点击及重复命令。 预期：次数与花费只一次。

**TC-MEM-06**　前提：已故人物或已终局家族。
操作：从旧详情提交新安排。 预期：拒绝写入，传记仍可阅读。

**TC-MEM-07**　前提：已经有工作经历的人。
操作：转行后再换回。 预期：能力、历史与实际人年保留。

### 年度与经济

**TC-YEAR-01**　前提：可正常推进且有保存状态。
操作：快速双击/触摸推进。 预期：只推进一个年度，费用收入和日志只写一次。

**TC-YEAR-02**　前提：有阻断事件或待选族长。
操作：点击年度推进。 预期：定位需要处理项，不偷偷跳过。

**TC-YEAR-03**　前提：年初在世与年末出生/加入的人。
操作：完成年度结算。 预期：收入和消费按明确时点规则，不重复或虚构劳动。

**TC-YEAR-04**　前提：现金不足但有粮食。
操作：结算卖粮补缺。 预期：粮减与现金增加相抵，非重复经营收入。

**TC-YEAR-05**　前提：口粮不足且现金有限。
操作：结算购买与短缺。 预期：只花实际有的钱，后果可见，不假称债已清。

**TC-YEAR-06**　前提：拥有作坊但无人从事手艺。
操作：读取预估与实结。 预期：没有经营收益；指明缺少经营者。

**TC-YEAR-07**　前提：年度中途模拟异常。
操作：恢复或重试。 预期：钱粮/人物/日志/RNG回退，重试不多走一年。

**TC-YEAR-08**　前提：长局与频繁查看各页。
操作：比较同种子模拟输出。 预期：视图行为不改变模拟结果。

### 家庭生命与关系

**TC-FAM-01**　前提：一位成年未婚成员。
操作：安排合法婚配。 预期：新成员独立入谱、双向配偶，主业继续。

**TC-FAM-02**　前提：同一婚事重复确认。
操作：重复命令。 预期：只新增一人并扣一次婚费。

**TC-FAM-03**　前提：父母/子女或共享已知祖先关系。
操作：尝试建立配偶关系。 预期：按明确世界关系规则拒绝。

**TC-FAM-04**　前提：双方关闭或一方关闭生育意愿。
操作：推进多个可生育年度。 预期：不会无视计划自然生育。

**TC-FAM-05**　前提：满足收养条件的家庭。
操作：接入孩子并成长。 预期：养亲来源清楚，成年可任族长。

**TC-FAM-06**　前提：保管信物并执行调查的成员离世。
操作：推进后查看物件/任务。 预期：历史保留、保管人回收、调查有接替或取消规则。

**TC-FAM-07**　前提：家中仅剩未成年人。
操作：继续推进。 预期：进入明确临时照护，不按族长无后判灭族。

### 族长与传承

**TC-LEAD-01**　前提：有多个成年不同性别/支系成员。
操作：选任一合法人接任。 预期：可选且任期成立，保留其他人状态。

**TC-LEAD-02**　前提：旧族长仍在世。
操作：完成主动交接。 预期：旧人仍在家族生活，不消失。

**TC-LEAD-03**　前提：旧族长离世，其他支系在世。
操作：进入下一步。 预期：可选继任，整局不结束。

**TC-LEAD-04**　前提：同年A→B→A。
操作：查看有效交接和终章进度。 预期：不刷传承资格；历史可记录实际任免。

**TC-LEAD-05**　前提：开局多代高能力成员。
操作：立刻往返换人。 预期：不算已经完成跨代培养/真实传承。

**TC-LEAD-06**　前提：没有候选者。
操作：打开继任界面。 预期：有说明/返回/监护状态，不能形成死循环弹窗。

### 信物与解锁

**TC-RELIC-01**　前提：带老木尺且现金足够。
操作：一年查访→推进→修复。 预期：后续按期，解锁营造图资格，总分仍100。

**TC-RELIC-02**　前提：选择慢查两年。
操作：推进一年及第二年。 预期：只在到期生成后续，不提前领奖。

**TC-RELIC-03**　前提：选择暂缓。
操作：日后从物件详情继续。 预期：可恢复且不会重复初始付费。

**TC-RELIC-04**　前提：调查在途物件出售。
操作：到期/重开旧后续/重复提交。 预期：无收益无解锁，已发生历史保留。

**TC-RELIC-05**　前提：保管人换任或死亡。
操作：查物件状态。 预期：物件仍属家族，可重新托付。

**TC-RELIC-06**　前提：资格已解锁。
操作：再次完成同一解锁。 预期：不重复Profile条目，不加总分，不自动给新局实体。

**TC-RELIC-07**　前提：未解锁医案开局资格。
操作：通过真实行医条件获得。 预期：局中能发现/取得并解锁，不存在解锁死循环。

**TC-RELIC-08**　前提：以后支持同类型多实例。
操作：出售其中一件。 预期：只取消对应实例后续，不误删另一件。

### 终章与事实

**TC-END-01**　前提：普通发展条件刚满足。
操作：继续游戏。 预期：仅出现落笔资格，不自动终局。

**TC-END-02**　前提：同一主终章已确认。
操作：再次提交确认。 预期：只一条主终章记录，RunState只读。

**TC-END-03**　前提：多个发展条件同时满足。
操作：选择其中一个。 预期：只选定者为主，其余作为资格旁注。

**TC-END-04**　前提：族长无子但其他人在世。
操作：检查自动终局。 预期：不会结束。

**TC-END-05**　前提：全员确实离世。
操作：年度结算结束。 预期：自动家谱落笔，保存可重读。

**TC-END-06**　前提：仍有在世成员。
操作：直接调用自动终局命令。 预期：命令层拒绝，不能只依赖界面隐藏。

**TC-END-07**　前提：初始资源很高或日期很晚。
操作：检查需要实际人年的结局。 预期：不借开局值伪造经历。

**TC-END-08**　前提：终章后规则版本升级。
操作：重读结局。 预期：使用当时快照，不篡改已完成史实。

### 存档与导入

**TC-SAVE-01**　前提：正常草案/Profile/Run。
操作：导出再导入。 预期：人物、关系、历史、RNG和资格一致。

**TC-SAVE-02**　前提：用户已有一局。
操作：导入窗口取消。 预期：原状态完整保留。

**TC-SAVE-03**　前提：损坏JSON、未知ID、循环亲缘。
操作：解析导入。 预期：隔离拒绝，不写坏现档。

**TC-SAVE-04**　前提：保存配额耗尽/权限拒绝。
操作：提交动作。 预期：提示临时/失败且可导出，不假显示已存。

**TC-SAVE-05**　前提：V3/V4/V5固定旧档。
操作：迁移预览及确认。 预期：保留实局日期/经历，只规范草案时间。

**TC-SAVE-06**　前提：新版价格高于旧版。
操作：载入已开始旧局。 预期：保留旧快照，不因当前超分拒绝续玩。

**TC-SAVE-07**　前提：解锁与事件结果保存中断。
操作：恢复最近有效修订。 预期：无只有奖励没扣款/只有结果没解锁的半提交。

**TC-SAVE-08**　前提：iframe/file来源改变或换设备。
操作：导入备份恢复。 预期：范围与存储隔离有说明，不承诺自动同步。

### 手机与内容状态

**TC-UI-01**　前提：360/390/430竖屏。
操作：走完创建与年度闭环。 预期：关键按钮可点，无页面级横向溢出。

**TC-UI-02**　前提：iOS/Android软键盘弹出。
操作：输入姓名和数字再保存。 预期：输入与保存不被键盘和底栏遮挡。

**TC-UI-03**　前提：底部面板/整屏详情。
操作：打开关闭、系统返回、Esc与Tab。 预期：焦点和滚动恢复，背景不可误触。

**TC-UI-04**　前提：系统字体放大和长文案。
操作：查看费用/禁用原因/选项。 预期：文本可读完整，不缩成小字。

**TC-UI-05**　前提：已结束、无结果、锁定、保存失败。
操作：访问各页面。 预期：都有明确状态与恢复路径。

**TC-UI-06**　前提：家史底部入口。
操作：切换族长史/年鉴/终章。 预期：所有子页仍可达，不因重设计消失。

**TC-UI-07**　前提：legacy144图鉴。
操作：筛选未实装条目。 预期：明示设计中、不可领取、不计正式数量。

**TC-UI-08**　前提：至少100条未来正式目录。
操作：审查published清单与路径差异。 预期：数量真实、不同阈值不重复凑数。

## 5. 发布前检查

- [ ] 原型基线、产品决策和发布说明一致。
- [ ] 必测用例全部有本构建结果；未测项目和风险明确。
- [ ] 真机与存档回归完成，不能用set_content替代。
- [ ] 按published目录核对实际内容；草案不计实装。
- [ ] 发布构建可重复，原文件/生成物校验一致。
- [ ] 用户能备份、恢复、继续旧局；回滚不破坏旧档。
- [ ] 每个关键动作在手机能独立完成。

## 6. 本包可直接执行的检查命令

```bash
python tools/build_prototype.py
python tools/verify_package.py
# 可选，先备好Python Playwright与Chromium：
python qa/smoke_v5.py --chromium /实际路径/chromium
```

前两个工具仅依赖Python标准库。浏览器检查会重新生成报告和截图；没有浏览器环境时可以跳过，但必须记录“未执行”，不能用空报告算通过。测试脚本使用内存存储，不验证跨浏览器真实localStorage策略。
