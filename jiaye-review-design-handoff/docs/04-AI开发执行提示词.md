# 给开发人员或编程 Agent 的执行提示词

先把整个交付目录放在可读取的位置。以下是本轮入口，优先于 baseline/v5 中的旧提示词。

```text
你正在维护《家业》，当前工程是 yyxhycj/family_simular 的 Lua/UrhoX 实现。
任务是修复行为回退，并实现最新“低压力、真随机、数值透明、手机紧凑开局”。
不要另造一个无关游戏，不因语言偏好整体重写，不擅自新增世界或改经济。

先读：
1. docs/00-先读-最新确认与版本优先级.md
2. docs/01-评审整改对照.md
3. docs/03-分步实施与验收.md
4. 本步相关的 docs/02-手机逐屏与数值绑定.md 与实际Lua源码。
视觉从 design/VIEW.html 进入。原评审位于 review/，针对历史提交
546ff6cf7e4225632fe9871ba70188e6aa730e82；先记录当前SHA并复核，
不要未经检查声称这些问题在现在仍存在或已经修好。

明确的产品结果：
- 默认生成一户完整且合法的家庭；看清关键数值即可开始，无需完成五页表单。
- 不是写死林家/谢家/贺家，也不是几户预制家庭轮播；关系模板可复用，成品家庭必须生成。
- 整户“换一家”、家族姓名骰子、本页随机为三个不同命令。
- 姓名可手改，零点；改名不动资质、资产、年龄和关系。外姓/复姓/自定义姓名正确处理。
- 查看、渲染、切页、算预估、开始不重掷。开始用正在展示的草案。
- 数值透明：首屏关键资产、人口/成员入口、信物、首年净变化、总分；全量明细点开。
- 五步编辑作为可选完整配置，沿用当前草案，可只改一项；所有原有配置仍可达。
- 一份100点预算，无类别配额，不要求满100，不自动删人降资质，超分/非法绝不开始。
- 初始3件信物是已解锁可选池，V5多选共享预算保留；不把图中示例罗盘等自动当已实现物件。
- 游戏仍纯文字、多代、全员可安排、族长可换；家族才是一局主体。
- 信物事件有参与人和不同故事；收藏与实体分开，新局保留收藏，总分不增长。
- 历史不删；生活与代际指标正确；终章凭真实经历，达标不自动截断。
- 最新插画只提供视觉与信息层级，不引入地图建造/战术战斗/修炼系统。

本次只执行一个T步骤；按依赖先T00，先修进度和事实再改UI。
给出本步修改文件、正常和失败路径、直接模块测试结果、必要录屏、尚未通过项。
原8探针是历史缺陷复现，不是正式模块验收；图片不是可运行Demo，也不是真机证据。
只有状态、记录、UI和存档都一致时才宣布本步完成。
```
