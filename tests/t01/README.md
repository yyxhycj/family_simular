# T01 直接模块验收

仅运行实际 `Jiaye.State` / `Simulation` / `App`，不复制玩法函数、不替换随机源。
使用 Lua 5.4；UI 适配器只收集组件与调用真实按钮回调，不模拟布局或绘制。
File 适配器在独立目录真实落盘，按 UrhoX 签名返回 boolean，并可注入打开失败、短写、错误返回 0、坏内容和写入异常。JSON 边界使用 Python JSON，不等同引擎 cjson。

```sh
python3 -m venv /private/tmp/jiaye-t01-venv
/private/tmp/jiaye-t01-venv/bin/pip install -r tests/t00/requirements.txt
/private/tmp/jiaye-t01-venv/bin/python tests/t01/run.py --out /private/tmp/jiaye-t01-evidence
```

输出目录必须尚不存在。任一断言失败即非零退出，不把已知缺陷改为预期通过。
每组结束后新建完整 Lua VM，从磁盘重启读取再检查，避免用进程内对象冒充重启。

六组验收：

1. `history`：151 条家史全量保存，第 1 条在第 8 页可查，翻页不改状态和随机源，重启后仍可查。
2. `succession`：真实年度离世产生唯一成年候选；事件页和人物页都完成任期、待决事件、奖励和日志；非法/重复不改变状态；旧卡死事件可修复；重启后推进下一年。
3. `collection`：真实老木尺调查解锁营造图；取消确认、取消新局均保留旧档；确认开始用眼前草案，收藏仍在、实体依选择、总分仍受 100 点约束；重复确认不重复创建。
4. `failed_new_run`：首次保存失败后原地重试；已有旧局时五类写入失败不替换当前 run，保留候选；超分拒绝，重启读取保留的旧局。
5. `failed_action`：安排已执行但保存失败时不显示成功，暂停后续安排和读取覆盖；导出失败如实提示，成功导出可恢复；重试保存不重复扣款、日志或计数。
6. `recovery`：兼容未编号现行存档；单份损坏从可读存档恢复；两份均损坏时阻止开局和覆盖；恢复文件后可继续。

`qa/t01/attempt-*` 保留执行结果与隔离存档。第一轮的三个失败来自测试边界适配（Box 参数、Lua 多返回值），没有标成产品通过。最终证据另见本步报告。

此测试不替代真实 UrhoX File/cjson、屏幕绘制、触控、安全区、录屏或真机验收；不覆盖 T02–T11 的随机生成、价格、代际、完整导入迁移等合同。
